# larva-scss

Core Sass tools and tokens for Larva: breakpoint mixin, functions, variables and generators. Sass files only; the consuming project (larva-css, brand themes) builds them.
Usage examples and breakpoint values: `packages/larva-scss/README.md`.

## Commands

```bash
npm test -- packages/larva-scss      # from the root; sass-true tests
npm run prod:scss                    # from the root, after changing a mixin: rebuild larva-css
```

## Public surface

- Public entry points are `dist/_tools.scss`, `dist/_tokens.scss` and `dist/_generators.scss`. `package.json` `main` (`lib/larva-scss.js`) does not exist; do not cite it.
- `dist/` is not build output. It is hand-written and `@import`s from `lib/`; edit it when the public surface changes.
- Implementation lives in `lib/` partials (`_name.scss`): `lib/tokens/`, `lib/tools/functions/`, `lib/tools/mixins/`, `lib/tools/generators/`.
- Private generator mixins are `_`-prefixed. Their public wrappers live in `dist/_generators.scss` (`lib/tools/generators/README.md`).
- Breakpoint names (complete list in `lib/tools/mixins/_pmc-breakpoint.scss`): `mobile-max`, `tablet`, `desktop`, `desktop-max`, `desktop-xl`, `desktop-xl-max`.

## Conventions

- Mixin, function and variable names are a public API for larva-css and every brand theme. Renaming or removing one is a breaking change (`UPGRADING.md`).
- Do not add new utility generators. New utilities belong in `packages/larva-css`, generated by iterating a token map (`README.md` note; `packages/larva-css/AGENTS.md`).
- Every behavior change gets a sass-true test: add `__tests__/<topic>.test.scss` (auto-discovered by `__tests__/larva-scss.test.js`) and run `npm test -- packages/larva-scss`.
- After changing a mixin, rebuild larva-css (`npm run prod:scss` from the root) and commit the regenerated CSS.

Avoid:

- Treating `dist/` as generated and skipping it in a change that adds a public mixin.
- Writing a new `token-utility-generator` call for a utility instead of a token-map loop in larva-css.

## Adding a tool

1. Add the partial under `lib/tools/{functions,mixins,generators}/` (imported from `lib/tools/_tools.scss`) or `lib/tokens/` (imported from `dist/_tokens.scss`).
2. Expose it through `dist/` if it is public (public generator wrappers go in `dist/_generators.scss`).
3. Add a `__tests__/<topic>.test.scss` and run `npm test -- packages/larva-scss`.
4. Rebuild larva-css from the root and add a CHANGELOG line (`* larva-scss - …`).
